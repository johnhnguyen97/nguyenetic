If you can read this at `/blog/hello-world`, the loader walked the filesystem,
validated frontmatter against the Zod schema, compiled MDX through
`next-mdx-remote/rsc`, and ran the rehype pipeline (Shiki, slug, autolink) on
the way to HTML. If `/ja/blog/hello-world` returns a 404, locale filtering is
working correctly.

## What this exercises

- **Frontmatter parsing** — gray-matter + Zod, fail-build on schema mismatch
- **MDX compilation** — server-side via `next-mdx-remote/rsc` (no client runtime cost)
- **Syntax highlighting** — Shiki with `min-dark` theme, server-only
- **Heading anchors** — `rehype-slug` + `rehype-autolink-headings`
- **Custom components** — like the `<Callout>` below, available inside MDX

## Code blocks render

Here's a small TypeScript snippet to verify Shiki is wired in:

```ts
import { z } from "zod";

export const PostFrontmatter = z.object({
  title: z.string().min(1).max(120),
  description: z.string().min(40).max(200),
  date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  tags: z.array(z.string()).min(1).max(6),
  lang: z.enum(["en", "ja", "zh", "ko", "vi"]),
});
```
